# In-game UI

Everything about the UI that `@pbgo/core` draws inside a game, always in the game's own look and never the platform's: first what core provides (screens, HUD, announcements, seat label, game over, skin), then the Game UI rules (chat, room for the cookie bar, theme contract, compact layout, motion, debug). The platform look is in `docs/design-system.md`.

## In-game UI of `@pbgo/core`

The in-game part of the `@pbgo/core` entry of `docs/packages.md`:

- Standard screens and game flow (from Courtisans): `Screen` (home, invitation, lobby), `GameHud` + `Ticker` + `groupTurns` + `useAnnouncements`, `GameOver` (`renderDetail` for the score detail), sound (`lib/sound.ts`, `SoundButton`, `SoundEngine`), `DesktopOnly`, leva debug panel, all mounted by `AppShell` in the `[game]` layout
- In-game UI (ticker, announcements, takeover pill, chat, game over, `PlayersStrip`, seat label): written once, drawn in the game's own look, never the platform's. The ticker, the takeover pill, the chat and the toolbar have no setting, they take the game's skin as they are. Three parts are tuned by `UI_THEME` of the binding (`UiTheme` in `lib/binding.ts`; `lib/ui-theme.ts` holds the defaults and `announcementTheme|seatTheme|gameOverTheme`): the announcements, the seat label and the game over. A game never restyles a component
- Pure view + connected wrapper: the announcements (`announcement-view.tsx`, `AnnouncementPresence` wraps it in `AnimatePresence`; `announcement.tsx` adds the sound, leva and the game), the game over (`game-over-panel.tsx`; `game-over.tsx` reads the game, shares the result and replays) and the strip (`players-strip-view.tsx`; `players-strip.tsx`) take props only, so `/design` draws the very same markup as the games. A change goes into the view; the specimens follow by themselves
- Seat label (`seat-label.tsx`, fed by `player-seat.tsx`): avatar + nickname + seat colour, the one way a player is named in the DOM (lobby, strip, announcements, game over). The tables paint the same avatar (`lib/seat-avatar-canvas.ts`, `SeatAvatarMesh` of each game). The avatar is generated (initial on the seat colour); an account picture (`imageUrl`, PLT-13) replaces it and nothing else changes. `UI_THEME.seat`: `shape`, `ring`, `font`, `name` (`"seat"` colour or `"ink"`)
- Announcements: four kinds (`start`, `round`, `turn`, `victory`), presets and timeline in `lib/announcement-settings.ts` (pure and tested; `announcementSettings(preset, UI_THEME.announcement)` seeds them). Sizes go through `vh()`, `calc(var(--vh, 1vh) * n)`: a screen reads the viewport, a stage that sets `--vh` (the `/design` specimens, scaled down) sizes like a screen of its own height. `UI_THEME.announcement`: `font`, `color`, `outline`, `shadow`, `veil`, `rule`, `confetti`
- Game over: the panel (winner, ranking, score chips from `renderDetail`, share thumbnail as a polaroid) in the game's surface. `UI_THEME.gameOver`: `surface` (any CSS background), `border`, `radius`, `ink`, `accent`, `frame`
- `DesktopOnly`: full-screen wall under 900 px on game pages only (`/<slug>/game/…`, the gamemaster's game preview included); the home and public pages stay readable on mobile (SEO), with `DesktopNotice` and no table creation from a narrow screen. The wall (`z-[100]`) sits above the cookie bar (`z-50`) like it does above the rest of the game page, so nothing is asked on that screen: the bar shows on the game home and the hub
- Skin (`lib/skin.ts`, `loadSkin`, `useSkin`, `useText`): Sanity `interface` (top/bottom art, character, pattern, host icon, player colors, desktop only) + `texts` (home intro, victory lines, `UI_TEXTS` labels of `@pbgo/studio-kit/constants`); a game's `DEFAULT_SKIN` only says how the skin behaves (player colours, desktop only), never a text or an image (a picture that is not in Sanity is not drawn, a required text that is not there reads `[missing: <key>]`, see `docs/sanity-and-languages.md`)
- Accent font (announcements, intro): CSS variable `--font-accent`, set by `themeStyle()` from the accent font file uploaded in Gamemaster › Visual (`settings.accentFontFile`, family `Site Accent`, served like the other uploaded fonts); a game with no file reads `var(--font-accent, var(--font-title))`, so the screens fall back to its title font. A game's CSS never declares a font file: fonts are Sanity files

## Game UI
- Settings menu (`components/toolbar.tsx`): a button next to the logo opens rules, sound, feedback, language and cookies
- Chat (`components/game/chat.tsx`, mounted by `GameHud`): Supabase realtime broadcast without storage; sent through `POST /api/<slug>/games/<code>/chat` (author = player cookie, member of the game, ≤ 200 characters or a known reaction), the server broadcasts (`lib/chat.ts`), clients only listen
- Turn crown left of the active player's nickname (template: `board/crown.tsx`; Courtisans: `CrownMark`)
- Game over: centered table, "hide / show" link above the centered PLAY AGAIN button
- Room for the cookie bar: a screen as tall as the viewport on a hub or game page subtracts the bar (`h-[calc(100dvh-var(--consent-h,0px))]`) and an element fixed to the bottom offsets by it (`bottom-[var(--consent-h,0px)]`), or a button of the game ends up under the bar. `packages/core/components/consent-room.test.ts` reads the classes of the hub, core's components and pages, the template and every game's `src` and fails on a violation; its allow-list holds the two layers that cover the whole screen on purpose (the narrow-screen wall and the game-over backdrop, which hold no button)
- Theme contract: `UI_THEME?: UiTheme` in the binding's `.` (isomorphic), all optional, CSS values only (`var(--accent-game)` works). Nothing declared = the defaults of `lib/ui-theme.ts`, the look the games had before they could tune it (white letters with a thin gold outline, gold hairlines and stars, a black veil; round seat discs; the skin's surface with a thin accent line and a cream polaroid), drawn with the game's skin tokens. Four groups: `motion` (`"calm"` by default: fades and short slides; `"lively"`: also confetti, springs and the emoji burst), `announcement`, `seat`, `gameOver` (fields above). Courtisans keeps its banquet in `games/courtisans/src/lib/ui-theme.ts` (gold line and stars on navy, `--font-accent`, round gold-ringed discs, lively); the template is "paper & ink" in `template/src/lib/ui-theme.ts` (cream on ink, vermilion rule, square seats, a paper panel, calm). A game never forks or restyles an in-game component: it asks for a field in `UiTheme`, which every game then gets
- Compact layout: the Tailwind variant `short` (`@media (max-height: 30rem)`, in `packages/core/styles/game.css`) is keyed on the viewport HEIGHT, because a phone held sideways (844×390) is wide but short. The HUD uses it (history behind a toggle, smaller announcement, chat collapsed to an icon, scrollable game-over panel, takeover pill stacked next to the logo, safe-area insets) and a game's overlays should too. The hub does not define it (the `/design` specimens do not draw the compact layout). `DesktopOnly` still hides game pages under 900 px wide: to check a table at 844×390, hide the wall with injected CSS in the browser, never in the code
- Motion: `motion/react` goes through `useMotion()` (`"reduced" | "calm" | "lively"`, `resolveMotion` in `lib/motion-preference.ts`) and `GameHud` mounts `MotionConfig reducedMotion="user"`. Reduced motion always wins over `UI_THEME.motion`: opacity fades of 150 ms at most, no confetti, emoji burst, springs or looping effects. CSS transitions use `duration-*` and `ease-standard` with `motion-reduce:transition-none`. Announcements stay up the same time and are read out in an `aria-live` region. Card and table motion is not part of the in-game UI: the flight, bend and hover of a card belong to the shared `Card` of `@pbgo/table`, which reads the easing curves of `components/game/easing.ts` (PLT-49), and the camera's entrance to its `Table`, which holds the camera still under reduced motion
- No copy in shared components: every label is a `UI_TEXTS` key, in the four languages (the strip uses `players`, `playersReady`, `seatDone`, `seatWaiting`, `seatAway`; the ticker `history`)
- `GameHud`'s root clips with `overflow-clip`, not `overflow-hidden`: a hidden box is still a scroll container, so a click or focus inside it could scroll the whole table out of place
- Debug: the leva panel opens with `Shift+D`, `?debug` or in development builds. The in-game UI only has the announcement presets in it (TRANSITION tab: duration, sound, scrim, fade, sizes, banner, confetti); a game adds its own scene knobs
