# Analytics

PostHog through `@pbgo/analytics`: typed events, the consent banner, recordings, masking and the scrubbing of table codes.

## Analytics (PostHog, `@pbgo/analytics`)
Optional: without `NEXT_PUBLIC_POSTHOG_KEY` and `NEXT_PUBLIC_POSTHOG_HOST` nothing runs (no request, no banner, no "Cookies" link). Vercel's `<Analytics />` is a separate, cookie-free measure and is unchanged. Every event carries `env` (`production`, `preview` or `development`: `VERCEL_ENV`, copied to `NEXT_PUBLIC_APP_ENV` by `next.config.ts`), the property that tells a real player from a test
- Events are typed in `packages/analytics/src/events.ts` (snake_case, `game` = the slug on every game event) and hold no personal data: never a nickname, chat text or table code. A new event = one entry there, then one line at the call site
- Server events (counted whatever the visitor answered): `trackAfter(event, playerId, properties)` of `@pbgo/core/server/analytics`, in `packages/core/routes/api/games/**`, after `updateGame` returns and never inside its modifier (that runs again when it loses a race). The id is the random value of the game's `<slug>_player` cookie, so nothing more is stored on the device; `identity_stable: false` until accounts exist (PLT-13), no person profile, no geolocation. `game_finished` is sent when the returned row is `over`; its `duration_s` and `moves_count` are approximations (`updated_at − created_at`, `version`) flagged `approximate: true`. Not tracked yet: `game_abandoned` (needs a sweeper)
- Browser: `AnalyticsProvider` is mounted by the hub, `[game]` and `global-not-found` root layouts, never by the gamemaster. The SDK talks to `/ingest` (rewritten to PostHog's EU hosts, `next.config.ts`; `skipTrailingSlashRedirect` is global because PostHog's endpoints end with a slash, and every canonical URL and the sitemap are explicit strings without one). Before the visitor answers it runs with `persistence: 'memory'` (nothing stored: each page load is a new anonymous visitor, so unique-visitor counts before consent are inflated). "Accept" switches to `localStorage+cookie`, calls `identify(<player id>)` at a table (`useIdentifyPlayer`) and starts session recording; "Refuse" or a withdrawal goes back to memory and sweeps the SDK's keys (`keys.ts`). `game_opened_from_hub` is counted from the hub's links that carry `data-game="<slug>"` (the hero button and the game cards: a new link from the hub to a game needs the attribute)
- The answer is `pbgo-consent` in `localStorage` (choice and date), asked again after 13 months (`consent.ts`). The banner (`CookieBanner` of `@pbgo/ui/platform`) is a single line docked to the bottom of the screen, never a card over the page: one sentence that ends with a "Details" link to `/legal#cookies`, then Refuse and Accept as the same button (FR/EN/ES/DE in `texts.ts`; `texts.test.ts` caps the sentence: one line on a desktop, 6.6% of a 1280×800 screen; on a phone it wraps to 3–4 lines beside the two stacked buttons, 9.4% of a 390×844 screen and 11.9% of a 375×667 one, and more below that (12.4% in English and 14.8% in German at 360×640), so a shorter sentence is the lever). The full disclosure (what is counted either way, what a refusal stores) lives in `/legal#cookies`, not in the bar. The banner and the "Cookies" links that reopen it (`ConsentLink`: hub footer, game home footer; the settings menu row) are hidden on pages that do not report: `/gamemaster`, `/design` and `/<slug>/preview/*` (`isExcludedPath`). The banner is `ph-no-capture` (its clicks are reported once, by `cookie_consent`, never by autocapture under the identity being given up; `banner.test.ts` keeps the class). What the visitor is told lives in `texts.ts` and in `/legal#cookies` (`(hub)/legal/page.tsx`): change them together with the behaviour
- The bar keeps its room free (`reserve.ts`, `reserveSpace`): the banner measures itself (a `ResizeObserver`) and publishes its height as `--consent-h` on `<body>`, with an inline `padding-bottom` of the same height, and removes both when it goes away (0px without a banner). Never on `:root`: the platform sets no value there, or every game would inherit it. A page that scrolls simply ends above the bar; a screen as tall as the viewport and an element fixed to the bottom do the arithmetic themselves (see `docs/game-ui.md`). The 3D canvas and the board area resize when the banner appears, is reopened from a "Cookies" link or closes
- Recordings mask every input; the chat is `ph-no-capture`, nicknames printed by core are `ph-mask` (the 3D scenes draw theirs in a canvas, which is not recorded). A game that prints a nickname in its own DOM adds `ph-mask` there, and `ph-no-capture` as well when it sits inside a button or a link: autocapture sends the text of a clicked `a` / `button` (`$el_text`), nested text included. Never set `maskTextFn` in `options.ts`: it replaces the stars of every masked node and would show the nicknames
- Table codes (`/<slug>/game/<CODE>`, `/api/<slug>/games/<CODE>/…`, and `Table #XXX-XXX` of the tab title) are scrubbed by `scrub.ts`: from every property of an event (`before_send`), from the page address, the links and the network timings of a replay (`maskCapturedNetworkRequestFn`, `maskAttributeFn`), and the `<title>` is masked in the replay (`maskTextSelector: "title"`). The code field is `ph-mask` too. A new place that prints the code needs the same care. The client's masking options win over the project's "Privacy and masking" settings: leave the project's text and block selectors empty. The recorder compresses its larger chunks (gzip), so check a replay after gunzipping it, never by searching the raw upload
- Not in the repo, set in the PostHog project `pbgo` (EU cloud): recording enabled for the domain, exception autocapture, web vitals, IP anonymisation, the internal/test-account filter, authorised URLs
