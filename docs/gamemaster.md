# Gamemaster

The back office at `/gamemaster`, one for every game of the registry: session, game switcher, sidebar, setup data, previews, tasks.

## Gamemaster (`/gamemaster`, all in English)
One back office for every game of the registry, live or not, in production too. A platform page: `@pbgo/ui/platform` only, its own root layout, no game runtime (components read the game through `useAdminSlug()` / `AdminGameProvider` and props computed on the server).
- Styles (`gamemaster/gamemaster.css`): `globals.css` (the platform layer) plus an `@source` for each folder of `packages/core` that renders inside the gamemaster (`components/admin`, `pages/admin`). `platform.css` only scans `packages/ui`, and Tailwind generates nothing for a class it never sees (the sidebar would lose `w-64`), so a new core folder rendered in the gamemaster is added there, not to the hub's stylesheet
- Session (`server/admin-session.ts`, pure and tested; cookie and checks in `server/admin.ts`): one for every game. Token `v1.<expiry>.<signature>`, HMAC-SHA256 with a key derived from `ADMIN_SESSION_SECRET`, the login and the password (changing any of the three signs everyone out), valid 7 days, compared in constant time. Cookie `gamemaster_session`: httpOnly, Secure (not in `next dev`), SameSite=Lax, `Path=/gamemaster`, so it only reaches the gamemaster pages, its API and the previews. The former `admin_session` cookie (path `/`) is cleared at sign-in and sign-out
- Closed unless configured: without `ADMIN_LOGIN`, `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` (32 characters at least) nobody gets in, and `/gamemaster/login` lists what is missing instead of the form (API: 403 `ADMIN_NOT_CONFIGURED`). Only `next dev` (`NODE_ENV=development`) with none of the three set is open, without sign-in
- Every page checks the session first (`/gamemaster/login?next=…`; `safeNext` in `lib/admin-nav.ts` keeps `next` on a page of the gamemaster), then the slug and the section (404). The API answers 401 `ACCESS_DENIED`. `POST /gamemaster/api/login` is rate limited (see Rate limiting in `docs/routing.md`)
- Game switcher (`components/admin/game-switcher.tsx`, top of the sidebar): every game of the registry with its initials and a Live badge; switching keeps the current section (`switchHref`; every game has every section) and asks before dropping unsaved changes. The overview (`pages/admin/overview.tsx`) shows each game's flags, Sanity project and whether saving to Sanity is connected, read from the environment only (no call to Sanity or Supabase)
- Sidebar (`lib/admin-nav.ts`, paths relative to `/gamemaster/<slug>`): **Setup** (Identity, Mechanics, Visual, Audio, Copy) · **Tasks** (Launch, Backlog, Bugs, Feedback) · **Monitoring** (Games, Audience, Health)
- Setup data: `server/settings.ts` (`readAdminData`, `saveSection(section, values)`, `uploadAsset(slot, file)`), routes `/gamemaster/api/<slug>/settings` and `/gamemaster/api/<slug>/upload/[slot]`. Sanity documents: `settings` (Identity, Mechanics, colors, and the body, title and accent fonts), `interface` (Visual images, player colors, desktopOnly), `audio` (music, ambience, effects, volumes), `texts` (Copy, including `errorMessages`)
- Upload conversions (`server/convert.ts`): images → WebP (SVG kept), favicon → PNG 512, share image → JPG 1200×630, TTF/OTF fonts → WOFF2. Sounds: MP3, 4 MB max
- Previews: iframe on `/gamemaster/<slug>/preview/home` and `/gamemaster/<slug>/preview/game` (fake game), draft sent by `postMessage` (`lib/preview.ts`, `components/preview-bridge.tsx`); API calls are neutralized there. A `beforeFiles` rewrite in `next.config.ts` serves those URLs from the game's own `[game]/preview/[kind]` page, so they render in the game's layout and skin while the browser still sends the `/gamemaster`-scoped cookie. `PreviewPage` answers 404 without the session and for a game with no engine; a game with one previews live or not (`previewableGameOf`). `/<slug>/preview/...` opened directly never sees the cookie
- Former URLs: `/<slug>/admin` and `/<slug>/admin/...` (slugs of the registry) redirect permanently (308) to `/gamemaster/<slug>/...`, the bare URL straight to Identity. The former admin API (`/api/<slug>/admin/...`, `/api/<slug>/tasks/...`, `/api/admin/login|logout`) moved under `/gamemaster/api` without a redirect
- Favicon and share image: `app/[game]/icons/*/route.ts`, `app/[game]/opengraph-image.tsx` → `@pbgo/core/metadata/images` (file uploaded in Identity, else generated from the logo and skin)
- Sounds: `lib/sound-config.ts` (types, the mix declared by the game: which effects exist and how they play), `lib/audio-server.ts` (`loadAudio`: the files, the music and the ambience come from the Sanity `audio` document only, nothing from the repo). An effect with no file in Sanity stays silent and is flagged "No file in Sanity" in Gamemaster › Audio and in Launch
- Absent player: `POST /api/<slug>/games/<code>/takeover` = per-player votes `(voter, target)` of the present players, kept in `games.takeover_votes` as `<state fingerprint>:<voter>:<target>` (stale as soon as a move is played, no custom route in any game)
- Tasks: table `tasks` (`type` backlog|bug, `priority`; `/gamemaster/api/<slug>/tasks[/<id>]`), table `feedback` (the game's feedback button, `POST /api/<slug>/feedback`, public; the gamemaster lists, updates and deletes it through `/gamemaster/api/<slug>/feedback`). Launch = checklist checked against the site (`server/launch.ts`), whose "Content" check lists every text a language is missing (`missingTexts` of `lib/missing.ts`, from the Copy page)
- Game options: defaults and hidden options set in Mechanics (`settings.options`, `gameOptions()` in `lib/settings.ts`)
