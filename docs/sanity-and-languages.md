# Sanity and languages

Where a game's content lives (one Sanity project per game, seeding, Studio forms, the media proxy) and the four languages (FR / EN / ES / DE) with the rule that a game's texts exist in Sanity only.

## Sanity
- One Sanity project per game (`sanityProjectId` in the registry), dataset `production`, studio `<slug>-studio` deployed to `<host>.sanity.studio`
- The studio reads its project id from `apps/studio/.env` (`SANITY_STUDIO_PROJECT_ID`, see `.env.example`) or from `sanity.cli.ts`
- A game's own content types: schemas in `apps/studio/schemaTypes`, queries in the binding's `src/sanity/`, then `pnpm --filter <slug>-studio typegen`
- Studio forms (what a game's owner fills in): the questions to ask the owner first, the rules and the don'ts are written once, in the skill `game-sanity-create` (`.claude/skills/`, see Rules of work in the root `CLAUDE.md`; `game-new` creates the game and hands over to it); `studio-forms.test.ts`, next to each `sanity.config.ts` (the template's, copied by `pnpm new-game`, and Courtisans'), keeps the rules that hold for the whole Studio true
- Seeding: a game's content (cards, credits, rulebook links, translations, art) is described in `games/<slug>/content/` (data and config) and written by the shared `@pbgo/content-kit` with `pnpm --filter @pbgo-game/<slug> content:seed --dry-run` then `--apply`. Drafts only (publishing stays in the Studio), idempotent, never overwrites what was edited in the Studio. Token `SANITY_API_WRITE_TOKEN_<SLUG>`, never printed. Process, options, art naming: `docs/content-pipeline.md`
- The platform's own project (`playboardgamesonline`, `mhgqs6fe`): the hub's catalog, articles, changelog and announcements, in `platform/`, see `docs/platform-sanity.md`. Its texts are in English until Sanity's translation system is plugged in; only the links to the rules are per language
- Media proxy `GET /api/media?url=` (shared by every game; fonts, sounds, SVG) only serves `https://cdn.sanity.io/(images|files)/<projectId>/…` where `<projectId>` is the `sanityProjectId` of a game of the registry (`sanityAssetUrl` in `packages/core/sanity/media.ts`, which also refuses `%` in the path and fetches the normalized URL). Core never imports the games: `apps/web/src/app/api/media/route.ts` passes the ids to `mediaRoute()`

## Languages (FR / EN / ES / DE)
- `LANGUAGES` in `packages/studio-kit/src/constants.ts` is the single source (it also feeds the Sanity `localeString` fields). Adding a language = add it there, then the translations below (TypeScript flags what is missing)
- Visitor language: cookie `pbgo-locale` (selector in the toolbar), else `Accept-Language` (unsupported language: English; no header: French). Same URL for everyone; `getLocale()` (`lib/locale-server.ts`) reads cookie and headers, so pages render on demand (Sanity data still cached 60 s)
- Shared texts: French in `UI_TEXTS`, default translations in `packages/studio-kit/src/translations.ts` (labels + errors). A text typed in the gamemaster (Copy) wins, language by language; without one in that language, the code's translation applies (never Sanity's French)
- A game's own texts, in every language, live in its Sanity project only (`texts`, `settings`, its own types); the binding has no `I18N`, no description, no tagline and no error message, and a game keeps no dictionary in its code. A required text that Sanity does not hold reads `[missing: <key>]` on the page (`packages/core/lib/missing.ts`: English, visible, never a crash), is logged once per language on the server where the Sanity data is merged, and is listed by the "Content" check of Launch. The optional ones (home title and introduction, the search-engine description) are not drawn when absent and are listed in Launch too. A game that needs more words than the shared `texts` has adds fields to it (`createTexts(extraFields, extraGroups)`, a Board tab for Courtisans) and reads them through its own loader. What stays in code is the platform's own chrome (`UI_TEXTS`, `translations.ts`, `CORE_ERROR_MESSAGES`) and the identity the platform needs before it reaches Sanity (`NAME`, `AUTHOR`, `CONTACT`, `KEYWORDS`). A few fallbacks stay inside the Sanity data, none in the code: the name of a family, a role or a mission, the description and the credits' authors read Sanity's French when their language has no value (`translate`, `toSettings`), so a visitor never reads a value Sanity does not hold
- Rules: no text document in Sanity (GAM-14), only a PDF link per language in `settings` (Gamemaster › Mechanics). The toolbar's Rules button opens the visitor's language, else English, else the first other language that has a link
