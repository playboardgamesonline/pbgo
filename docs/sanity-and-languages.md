# Sanity and languages

Where a game's content lives (one Sanity project per game, seeding, Studio forms, the media proxy) and the languages: the games' four (FR / EN / ES / DE) and the platform's twelve, with the rule that a game's texts exist in Sanity only.

## Sanity
- One Sanity project per game (`sanityProjectId` in the registry), dataset `production`, studio `<slug>-studio` deployed to `<host>.sanity.studio`
- The studio reads its project id from `apps/studio/.env` (`SANITY_STUDIO_PROJECT_ID`, see `.env.example`) or from `sanity.cli.ts`
- A game's own content types: schemas in `apps/studio/schemaTypes`, queries in the binding's `src/sanity/`, then `pnpm --filter <slug>-studio typegen`
- Studio forms (what a game's owner fills in): the questions to ask the owner first, the rules and the don'ts are written once, in the skill `game-sanity-create` (`.claude/skills/`, see Rules of work in the root `CLAUDE.md`; `game-new` creates the game and hands over to it); `studio-forms.test.ts`, next to each `sanity.config.ts` (the template's, copied by `pnpm new-game`, and Courtisans'), keeps the rules that hold for the whole Studio true
- Seeding: a game's content (cards, credits, rulebook links, translations, art) is described in `games/<slug>/content/` (data and config) and written by the shared `@pbgo/content-kit` with `pnpm --filter @pbgo-game/<slug> content:seed --dry-run` then `--apply`. Drafts only (publishing stays in the Studio), idempotent, never overwrites what was edited in the Studio. Token `SANITY_API_WRITE_TOKEN_<SLUG>`, never printed. Process, options, art naming: `docs/content-pipeline.md`
- The platform's own project (`playboardgamesonline`, `mhgqs6fe`): the hub's catalog, articles, changelog and announcements, in `platform/`, see `docs/platform-sanity.md`. Its catalog is translated field by field in twelve languages, English the default and the fallback (`PLATFORM_LANGUAGES`, `sanity-plugin-internationalized-array`, PLT-104); its editorial documents stay in English until their own pass
- Media proxy `GET /api/media?url=` (shared by every game; fonts, sounds, SVG) only serves `https://cdn.sanity.io/(images|files)/<projectId>/…` where `<projectId>` is the `sanityProjectId` of a game of the registry (`sanityAssetUrl` in `packages/core/sanity/media.ts`, which also refuses `%` in the path and fetches the normalized URL). Core never imports the games: `apps/web/src/app/api/media/route.ts` passes the ids to `mediaRoute()`

## Languages (the games' four, the platform's twelve)
- Two sets, on purpose. The **platform's twelve** (`PLATFORM_LANGUAGES` and `DEFAULT_PLATFORM_LANGUAGE` in `packages/studio-kit/src/constants.ts`: English first, the default and the fallback of every text, then fr, es, de, zh (Simplified Chinese), ja, ru, ar, bn, hi, pt, ko) are the languages a visitor can choose, kept on their account and in the cookie (`docs/accounts.md`, "The visitor's language"), and the languages of the platform's own content: its catalog is translated field by field, an array of rows `{ language, value }` instead of a value, and nothing filled in a language means English (`@pbgo/studio-kit/field-translations` sets the plugin up, `docs/platform-sanity.md` has the model, the rules and the migration). The **games' four** (`LANGUAGES`, the same file: FR / EN / ES / DE) are the languages a game's site and Studio render until the game lane moves them to the same system. The four are among the twelve, and a visitor whose language a game lacks reads English there (`localeFor` in `packages/core/lib/i18n.ts`)
- `LANGUAGES` is the single source of the games' languages (it also feeds the Sanity `localeString` fields). Adding a language there = add it there, then the translations below (TypeScript flags what is missing). The platform's other eight do not go into it: every game's forms map over it
- **English is the default language and the fallback of every text** (PLT-103, the owner's decision of 2026-11-02): `DEFAULT_LOCALE` is `en`, the site is read in English unless the visitor asked for another language, and the other languages are options. The chain of a text is the language asked, then English, then nothing, which the page shows as `[missing: <key>]` for a text it requires and leaves out for one it does not. Never French (the default before English), never "the first language that has a value". It is `translate()` of `packages/core/lib/i18n.ts`. `written()` is the one exception, on purpose: what a game's owner typed to replace a label of the interface or the message of one of the platform's errors counts only in the language it is written in, because the platform words those in every language of the games and a label typed in English must not take the place of the Spanish one. `only()` is a deprecated alias of `translate()`
- Visitor language: cookie `pbgo-locale` (any of the twelve; the picker in the toolbar and the Language row of `/me/settings/language` write it through one setter, which also writes the visitor's account), else `Accept-Language` (the first language of the games' four that the browser asks for), else English: a browser in a language the games lack, and a request with no header at all (a crawler), get English. A cookie that holds a language the games lack gives English, not the language the browser comes second with. Same URL for everyone; `getLocale()` (`lib/locale-server.ts`) reads cookie and headers, so pages render on demand (Sanity data still cached 60 s)
- Shared texts: the platform's chrome has its wording in code in each of the games' four languages. English is the default skin's (`UI_TRANSLATIONS.en`, with the platform's error messages `CORE_ERROR_MESSAGES`, which a test keeps equal to `ERROR_TRANSLATIONS.en`), French is the text each `UI_TEXTS` entry carries (`UI_TRANSLATIONS.fr`), Spanish and German are in `packages/studio-kit/src/translations.ts` (labels + errors). A text typed in the gamemaster (Copy) wins, in its language only; without one in that language, the code's translation of that language applies, never another language's. The ten error messages that came with the shared error vocabulary (`ENGLISH_ONLY` in `packages/core/lib/language-chain.test.ts`) are English only: the code holds English, and the language pass translates them with the rest of the interface (PLT-32), a visitor reading English until then. So are the three labels of the defeat of a table that lost together (`ENGLISH_ONLY_TEXTS` in `packages/studio-kit/src/constants.ts`: the entries of `UI_TEXTS` carry the English where `fr` goes, `translations.ts` gives it to the other languages, and a test keeps them equal)
- A game's own texts, in every language, live in its Sanity project only (`texts`, `settings`, its own types), the words of its engine's options, presets and score lines included (`texts.engineTexts`, listed in Copy › Options); the binding has no `I18N`, no description, no tagline and no error message, and a game keeps no dictionary in its code. A required text that Sanity does not hold reads `[missing: <key>]` on the page (`packages/core/lib/missing.ts`: English, visible, never a crash), is logged once per language on the server where the Sanity data is merged, and is listed by the "Content" check of Launch. The optional ones (home title and introduction, the search-engine description) are not drawn when absent and are listed in Launch too. A game that needs more words than the shared `texts` has adds fields to it (`createTexts(extraFields, extraGroups)`, a Board tab for Courtisans) and reads them through its own loader. What stays in code is the platform's own chrome (`UI_TEXTS`, `translations.ts`, `CORE_ERROR_MESSAGES`) and the identity the platform needs before it reaches Sanity (`NAME`, `AUTHOR`, `CONTACT`, `KEYWORDS`). The fallback is inside the Sanity data, none in the code: the name of a family, a role or a mission, the description and the credits' authors read Sanity's English when their language has no value (`translate`, `toSettings`), and `[missing: <key>]` when English has none either, so a visitor never reads a value Sanity does not hold and never reads French by accident. The Launch check lists a text only in the languages that would read a gap (`gapsOf`: none while English has a value) and asks for the English rulebook
- Rules: no text document in Sanity (GAM-14), only a PDF link per language in `settings` (Gamemaster › Mechanics). The toolbar's Rules button opens the visitor's language, else English, else the first other language that has a link: a rulebook is a document, not a text, so it is not left out when only another language has one (the owner's chain above is for texts; say so if it should apply here too, and the button would then be drawn only for a language or English that has a link)
