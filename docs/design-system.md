# Design system

The two token layers of `@pbgo/ui` (platform and game), the palette, and the rules for components. The page `/design` shows every token and component: check it before building a screen.

## Design system (`@pbgo/ui`)
Black and white, dark theme only, Geist Sans in semibold with tight line-height and letter-spacing. No accent colour, and a single gradient, neutral too: the backdrop of the home's hero (`bg-linear-to-b from-secondary via-card to-background`), lighter at the top and black where the games start. Game art is the only colour on the platform. Every token and component is shown on the internal page `/design` (`(hub)/design/page.tsx`, noindex, not in the sitemap): it is the reference, check it before building a screen.
- Two layers share the token names (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, `--radius`, `--font-body`…):
  - Platform layer (hub, account, legal, admin, 404): values in `packages/ui/src/styles/platform.css`, scoped to the class `.platform`. The class sits on `<html>` (hub and 404, through `PlatformDocument`), on the admin wrapper and on the root of every portal (select, dropdown, dialog, sheet, tooltip, toast), which React renders outside the wrapper. Components: `@pbgo/ui/platform/*`
  - Game layer: the `:root` values of `packages/core/styles/game.css`, overridden at runtime by the game's Sanity skin (inline style on `<html>`, `themeStyle()`). Components: `@pbgo/ui/game/*`. A game changes its look by changing token values, never a component
- Boundary: the platform never sets a value on `:root` and a game never sets one on `.platform`. In `platform.css`, `@theme` only defines new names (`shadow-surface|float|overlay`, `duration-fast|base|slow`, `ease-standard`, `bg-scrim`, `max-w-page|reading`, `px-gutter`, `py-section`, `h-navbar|pt-navbar|scroll-mt-navbar`); a name Tailwind already has (type-scale line-heights, `--tracking-tight`, `--default-transition-*`, `--font-weight-*`) gets its platform value inside `.platform`, or every game would inherit it
- In-game UI: not part of the platform layer. It is drawn in the game's own look (its skin tokens `--foreground`, `--surface`, `--accent-game`, `--font-title`, `--font-accent`, set by `themeStyle()`), tuned by `UI_THEME` (see `docs/game-ui.md`); never `@pbgo/ui/platform`, Geist or the `.platform` class. `/design › In-game UI` is the one place where the hub shows it: two games (Courtisans and the template) side by side, each inside a `GameScope` (`_components/game-scope.tsx`) that resets the platform's values (Geist, weight, line-heights, tracking, radius) and sets the game's tokens and font stacks on its own wrapper, never on `:root`. The hub does not load `game.css`: `globals.css` points `@source` at the four pure components (`seat-label`, `players-strip-view`, `announcement-view`, `game-over-panel`) and maps the utilities only games have (`font-display`, `bg-surface`, `bg-surface-dark`, `text-accent-game`) with `@theme inline`, which emits no variable. A new pure component drawn on `/design` needs its `@source` there. The font files of a game are not loaded on the hub, so its families fall to the next of the stack (Georgia); the colours, layout and motion are the real ones. Use `data-look`, never `data-game` (analytics counts the hub links that carry it)
- Palette: Tailwind's `neutral` scale (chroma 0) and `destructive`, nothing else. One font weight (600): `font-medium`, `font-bold`… resolve to it, so don't write them. Depth: `shadow-surface|float|overlay` and `ring-1 ring-foreground/10`. Motion: `duration-fast|base|slow`, `ease-standard`. Shapes: `rounded-*`, scaled from `--radius`
- Popovers (select, dropdown menu, popover) are translucent (`bg-popover/70`) and carry their blur on the popover element itself (`backdrop-blur-2xl backdrop-saturate-150`), never on a `::before`. A descendant with a blend mode (the `Avatar` ring is `mix-blend-lighten`) makes the popover an isolated group in Chromium, and a pseudo-element backdrop then blurs nothing: the page shows through the list, sharp. The game switcher (an `Avatar` in each of its rows) is the live check of this rule
- `PLATFORM_THEME_COLOR` (`@pbgo/ui/theme`) is the browser colour of platform pages; `theme.test.ts` keeps it equal to `--background`. `platform.test.ts` rejects `dark:`, palette and hard-coded colours, arbitrary sizes and the old `admin` names in `packages/ui/src/platform/*`
- The hub's game card is `GameCard` (`@pbgo/ui/platform/game-card`), built on `GameCardVisual`, its picture: the game's logo over its background on the `bg-muted` frame, no layer between the two (no scrim: the art shows as it is), the frame alone when there is neither. The page of a game on the hub draws the same `GameCardVisual`, larger, so the card and the page cannot drift apart. `/design` (section `game-card`) shows the card of a live game and of a game to come, then the picture alone
- The hub's navbar is `Navbar` (`@pbgo/ui/platform/navbar`), with `Logo` and `SearchBar` beside it: hand-written, not from shadcn, shown on `/design` (sections `logo`, `navbar`, `search-bar`). `Navbar` is two containers kept apart over a transparent bar, `h-navbar` high: `NavbarStart` on the left (the brand, then the tabs) and `NavbarEnd` on the right (the account: an avatar of `size-10`, or Sign in and Sign up as `lg` buttons). Each is a glass island, a rounded square (`h-14 rounded-2xl border bg-background/80 shadow-surface backdrop-blur-md`, its content `h-10` and `rounded-lg`: the island's radius less its `p-2`, so the corners stay concentric; `NavbarEnd` makes the buttons in it `rounded-lg` too, a button being a pill elsewhere) that takes the pointer back, while the bar between the two lets the page and the pointer through. The bar spans the window, not the page's `max-w-page`: the islands sit on its edges, `0.75rem` in from the top and from each side. The brand is the home's button, a `size-10` tile around the `Logo` (`h-6`, the size of the tabs' text): on the front page it is `current`, white (`bg-primary`) with a black logo, and no tab is; on any other page it is as quiet as a tab and the page's tab is the current one. The page pins the bar (`fixed inset-x-0 top-0 z-40`), then leaves `pt-navbar` under it or lets the backdrop of its first screen run under the islands (the home's hero does), and gives an anchor that lands below it `scroll-mt-navbar`; the tabs leave the first island under `md`. `Logo` is an inline SVG on `currentColor`, since `apps/web/public` holds `favicon.ico` only. `SearchBar` draws the search pill and nothing else: the page owns the text and what it finds (the home lays the bar over the bottom of its title, in the hero: its top edge sits on the baseline of the last line, so the letters stand on it and the tails of the script letters pass behind it)
- The filters of the hub's search bar are segments in the bar (`SearchBarSegments` and `SearchBarSegment` of `@pbgo/ui/platform/search-bar`: an icon, a small label and what is picked, dimmed while nothing is), each opening a `Popover` (`@pbgo/ui/platform/popover`) of chips (`ToggleGroup`, `@pbgo/ui/platform/toggle-group`). Like the navbar they are hand-written, not from shadcn, and shown on `/design` (sections `search-bar`, `popover`, `toggle-group`). With segments the bar has two floors at any width, the field and the round button on top and the filters under a line: a row of four from 42rem of room and a 2 × 2 grid below, which it asks its container (`@container`, `@2xl`) for, not the window, so the same bar fits the home's hero and a narrow column. The panel is portaled, so like every portal it carries the `platform` class itself, and it sits at `z-50`, above the navbar's `z-40`. A chip that is picked is `bg-primary`; a `single` group reports an empty string when its picked chip is clicked again, which the page reads as no pick
- The title of the home is set in four display faces, one per letter, by `LetterMix` (`@pbgo/ui/platform/letter-mix`, section `letter-mix` of `/design`): a text in capitals (CSS: `letter-mix`, so the text stays one string, written as it is, for a screen reader and a search engine) whose letters are plain inline `span`s of `letter-face-1` to `letter-face-4`. Those are utilities of `platform.css`, each the family, the one weight and the size of a typeface: UnifrakturMaguntia, Unkempt (700), Jersey 15 and Birthstone Bounce (500), Fontsource packages (`@fontsource/*`, the latin subset) that `apps/web/src/app/globals.css` imports, so a game page never carries them. Each face sets its own weight, since the platform's 600 on a face that has none would be a fake bold, and a scale of the parent's size that gives it the cap height of Geist's capitals (measured, not guessed). A letter has `line-height: 0`, so the lines of the title keep the element's own height whichever faces they got and nothing moves when a font file arrives. The faces are dealt like a deck (a shuffled bag of the four, used up one letter at a time: each comes once in every four letters, never twice in a row, in an order that looks random) from a `seed`, so the server and the browser deal the same; the home gives its two lines two seeds. It is for a page title only, from `text-3xl` up: the capitals of the blackletter and the script are the hardest to read. A face is swapped in `platform.css` and in `globals.css`, nowhere else; `letter-mix.test.ts` keeps the deal (the same on every render, no face twice in a row, each once in four) and the markup (one string) from drifting
