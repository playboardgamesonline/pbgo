# Moving the project to another account

The project lives on oré's accounts: GitHub (`playboardgamesonline/pbgo`), one Vercel project (`pbgo`, id `prj_bsk7OjC3wkJrI6ElHFa8bfD71xfs`), one Sanity project per game and the platform's own (`mhgqs6fe`, `docs/platform-sanity.md`), one Supabase project for production and one for previews (`pbgo-preview`).

Defaults tied to the current accounts, all overridable:
- `scripts/setup-env.sh`: the Vercel project id (`prj_bsk7OjC3wkJrI6ElHFa8bfD71xfs`), used when `VERCEL_PROJECT_ID` is not set in the secrets file. The project is always looked up by its id, never by its name, so a rename changes nothing. The Vercel team is not a default: `VERCEL_TEAM_ID` is required whenever there is a `VERCEL_TOKEN`
- `scripts/go-live.sh`: new Sanity projects go to the organization named "Main", else to the organization of the Courtisans project
- `packages/core/lib/site-url.ts`: `https://playboardgamesonline.app`, unless `NEXT_PUBLIC_SITE_URL` is set
- Author and publisher shown on the pages: `AUTHOR` in each game's `src/lib/site.ts`, `PUBLISHER` in `apps/web/src/site.ts`

## Recommended order

1. **GitHub**: Settings › Transfer ownership of the repository. Issues, pull requests and history follow; the old URL redirects.
2. **Vercel**: the receiving team needs the GitHub integration. Transfer the project `pbgo` (Settings › Advanced › Transfer Project): environment variables, the domain `playboardgamesonline.app` and deployments follow. Reconnect the repository if Vercel asks. Then set `VERCEL_TEAM_ID` to the new team and `VERCEL_TOKEN` to a token that reaches it (secrets file; `apps/web/.env.local` is only the fallback), and `VERCEL_PROJECT_ID` in the secrets file to the project's id there (Project Settings › General) if it differs from the default. `pnpm setup-env` reads the API with that token alone: it has no default team and never uses the Vercel CLI login.
3. **Sanity**: for each game (`sanityProjectId` in `packages/games/src/registry.ts`) and for the platform's own project (`mhgqs6fe`; its write token, `SANITY_API_WRITE_TOKEN_PLATFORM`, lives in `apps/web/.env.local` only, `pnpm setup-env` does not push it), sanity.io/manage › project › Settings › Transfer project, or invite the new account as Administrator. Then replace the write tokens as a precaution. `pnpm setup-env` reuses any token it finds (the secrets file, then `apps/web/.env.local`, then the Vercel project), so remove each `SANITY_API_WRITE_TOKEN_<SLUG>` from all three, revoke the old ones (sanity.io/manage › project › API › Tokens), then run `pnpm setup-env`: it creates the missing tokens with the `npx sanity login` session and pushes them to Vercel.
4. **Supabase**: Project Settings › General › Transfer project, for the production project and `pbgo-preview`. The keys don't change. Update `~/.config/pbgo/secrets.env`: `SUPABASE_ACCESS_TOKEN` (a token of the new account), `SUPABASE_PROJECT_REF`, `SUPABASE_PREVIEW_PROJECT_REF`. All three are required: `pnpm setup-env` stops without them, and never writes the production keys outside the Vercel Production target. It also applies the pending `supabase/migrations` to both projects, recorded in `supabase_migrations.schema_migrations`, a table that moves with the project: a project that has them all needs nothing.
5. **Domain**: `playboardgamesonline.app` follows the Vercel project; otherwise attach it to the new team (Domains › Transfer, or add it again to the project).
6. **Git identity**: update `git config user.email` on every machine. It must be the address of the GitHub account that deploys, or Vercel blocks the deployment.
7. **Variables to check after the move** (Production, Preview, Development): `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`, `SANITY_API_WRITE_TOKEN_<SLUG>`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, `VERCEL_ANALYTICS_PROJECT_ID`, `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST` (the last two are inlined at build: redeploy after a change; a new PostHog project also needs its own settings, listed in `docs/analytics.md`), `NOTION_API_KEY` (optional; if the Notion workspace changes, create a read-only integration there and connect it to the Games and Editors databases, see `docs/catalog.md`). `pnpm setup-env` sets them from the secrets file.
