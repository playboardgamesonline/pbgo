# Platform · the platform's own Sanity project

`playboardgamesonline` (project `mhgqs6fe`, dataset `production`, public): what the hub says about games, apart from each game's own project. Package `@pbgo/platform`. The detail (the model and why, the seed, the pictures, what to publish first) is `docs/platform-sanity.md`; this file is the map.

## Structure
- `apps/studio` — `platform-studio`, built with `createStandaloneStudioConfig` of `@pbgo/studio-kit` (none of a game's shared singletons). `pnpm dev:studio platform`; deployed at `pbgo.sanity.studio`
  - `schemaTypes/` — `game`, `expansion`, `creator`, `publisher`, `category` (the catalog), `article`, `changelogEntry`, `announcement` (the editorial), the `gameCreator` line of the credits of a game and of an expansion, the rules of validation they share (`rules.ts`, those of the translated fields included), the kinds of translated value that the plugin gets and `translatedField`, which makes a translated field with its rules and its initial value (`translations.ts`) and the lists the seed shares (`constants.ts`: no import from Sanity there, `TRANSLATED_FIELDS` the translated fields of each type)
  - `structure.ts` — the sidebar, three blocks: Catalog, Editorial and Shop (empty on purpose: no document type for it yet), the "Games" tab of a creator and of a publisher and the "Expansions" tab of a game; `views/` holds those tabs (`games-of.ts` and `expansions-of.ts` the queries, `games-of-view.tsx` and `expansions-of-view.tsx` the parts that need the Studio)
  - `studio-forms.test.ts` (the rules of the forms of the skill `game-sanity-create`), `schemaTypes/model.test.ts` (the model as agreed: change it only on purpose), `schemaTypes/rules.test.ts`, `schemaTypes/translations.test.ts` (the schema compiled with the plugin), `structure.test.ts` (the sidebar and the tabs, against a stand-in for the structure builder), `views/games-of.test.ts` and `views/expansions-of.test.ts` (the queries, run by a GROQ engine)
- `content/` — the seed, run by the shared `@pbgo/content-kit`
  - `seed.ts` (`runSeedCli` with a `content` that reads Notion), `fetch-art.ts` (the Notion pictures into a folder outside the repo), `notion.ts` (the games in the order the hub used to list them, the Editors rows) with `notion/` (the Notion reader and `hubOrder`: the hub reads this project now, PLT-90, and Notion is only this seed's source), `art-files.ts` (what to download and how), `config.ts` (project, dataset, token name)
  - `data/` — the documents: `games.ts`, `expansions.ts` (none are seeded yet: the Notion reader only counts the expansions), `shared.ts` (what a game and an expansion take from a row alike), `translated.ts` (the rows of a translated field, `withEnglishRows`), `taxonomy.ts` (creators, publishers, categories), `art.ts` (the slots), `ids.ts`, `index.ts`; the fixtures and tests (`data.test.ts` the documents, `schema.test.ts` against the Studio's own types, `run.test.ts` through the runner and an in-memory dataset)
  - `migrate-expansions.ts` and `migration/` — the one-off move of the expansions made as games to the `expansion` type (PLT-102, done): `expansions.ts` the plan and its words, `http-store.ts` the dataset side, tested with an in-memory dataset and a fake `fetch`
  - `bgg-figures.ts` and `bgg/` — the figures of the games from BoardGameGeek, as drafts (PLT-78): `xml.ts` the reader of BGG's XML, `client.ts` its API with the token, `figures.ts` the plan and its words, `ids.ts` the search of the ids by name, `store.ts` the dataset side; each tested with a fake `fetch` and an in-memory dataset
  - `migrate-translations.ts` and `migration/translations.ts` — the conversion of the catalog to the translated fields (PLT-104), published documents and drafts patched in place; `snapshot-store.ts` plans against a file (`--from`), `translations-fixtures.ts` the documents of the tests

## Rules
- English everywhere in the code and in the Studio's own labels. The catalog's content is translated field by field in thirteen languages, English (US) the default and the fallback and English (UK) falling back on it (`PLATFORM_LANGUAGES`, PLT-104, PLT-128): a translated field is an array of rows, and **whatever writes one gives English its row, empty if need be** (the plugin of the Studio writes a missing one when a document is opened, which makes a draft of a published document). A translated field added later: `TRANSLATED_FIELDS`, `translatedField` in the type, then `content:migrate-translations` (`docs/platform-sanity.md`)
- The seed writes drafts only and publishes nothing, and writes its references weak and marked to be made strong on publication (the dataset refuses a strong one to a document that is not published, a draft's included). Creators, publishers and categories are published before the games, and the games before their expansions; `related` is weak for good. Never run `content:seed --apply`, `content:migrate-expansions --apply`, `content:migrate-translations --apply`, `content:bgg --apply` or deploy the Studio without the owner's go
- The Studio forms follow the skill `game-sanity-create`: no description under a field, the title says it; the `game` in tabs
- A document type added to the seed gets its tests in `data/` and a line in `docs/platform-sanity.md`; the model's shape is pinned by `schemaTypes/model.test.ts`

## Commands (from the root)
- `pnpm --filter @pbgo/platform content:seed [--dry-run | --apply] [--art-dir <folder>]` — `--help` for the options
- `pnpm --filter @pbgo/platform content:art --out <folder> [--apply]` — the Notion pictures, into a folder outside the repo
- `pnpm --filter @pbgo/platform content:migrate-expansions [--dry-run | --apply]` — the expansions made as games → the `expansion` type, in one transaction; a dry run by default (`docs/platform-sanity.md`)
- `pnpm --filter @pbgo/platform content:migrate-translations [--dry-run | --apply] [--from <file>] [--verbose] [--show <id>]` — the texts and pictures of the catalog → the translated fields, in one transaction; a dry run by default, `--from` plans against a file of documents with no token (`docs/platform-sanity.md`)
- `pnpm --filter @pbgo/platform content:bgg [--dry-run | --apply] [--find-ids | --set-ids]` — the missing figures of the games (complexity, players, duration, age) from BoardGameGeek, as drafts; a dry run by default; needs `BGG_API_TOKEN` (`docs/platform-sanity.md`)
- `pnpm --filter @pbgo/platform test` · `typecheck`, `pnpm --filter platform-studio test` · `typecheck`
- `pnpm --filter @pbgo/platform deploy:studio` — only with the owner's go
