# Play Board Games Online · monorepo

oré's online board games in one repository (`playboardgamesonline/pbgo`), a pnpm workspace served by **one Next.js app** on `playboardgamesonline.app`: the hub at `/`, each game at `/<slug>`, and the back office of all of them (the gamemaster) at `/gamemaster`.

Moving the project to another account: see `MIGRATION.md`.

This file is a map: structure, routes, commands, rules of work. The detail of each area is in `docs/` (list at the end, Where to read more).

## Structure
- `apps/web/` — `web`, the only Next.js app (hub, every game and the gamemaster). Vercel project `pbgo`, root directory `apps/web`
- `games/<slug>/` — one game = packages only, no app of its own:
  - `src/` — the binding package `@pbgo-game/<slug>`: site constants, engine binding, board, server loaders, sounds, defaults, i18n, skin
  - `packages/engine` — `@<slug>/engine`, the pure TypeScript engine (no UI), tested with Vitest
  - `apps/studio` — `<slug>-studio`, the game's Sanity Studio
  - `content/` — the game's Sanity content as versioned code (its data and its config) and a seed script that writes drafts, run by the shared `@pbgo/content-kit` (Hanabi, Exploding Kittens and Flip 7, see `docs/content-pipeline.md`)
  - `assets/` — sources (PDF, PSD, HD visuals), git-ignored. The seed's art folder is outside the repo (Hanabi: `~/Companies/PBGO/assets/hanabi`) and is passed with an absolute `--art-dir`
- `template/` — the game template, itself a game (`@pbgo-game/template`, demo "La Plus Haute", served at `/template`). See `template/CLAUDE.md` and `template/docs/GAME_GUIDE.md`
- `platform/` — the platform's own Sanity project (the hub's catalog, articles, changelog, announcements), package `@pbgo/platform`: `apps/studio` (`platform-studio`, its Studio) and `content/` (the seed that imports the Notion Games rows). See `docs/platform-sanity.md`
- `packages/` — shared code (below)
- `docs/` — the detail behind this map, one file per area (see Where to read more), and `content-pipeline.md` (seeding a game's Sanity content)
- `supabase/migrations/` — schema of the single Supabase project
- `scripts/` — `new-game.sh`, `go-live.sh`, `add-game.sh`, `game-rules.sh`, `setup-env.sh` (helpers in `lib.sh`), `run.sh`, `check-catalog.mjs`
- `.claude/skills/` — the agents' skills by category (`game-`, `engine-`, `platform-`): the questions, rules and commands of a recurring job, written once. `README.md` lists them

## Games registry and shared packages (`packages/`)
A change in `packages/` reaches every game on the next deployment. Detail: `docs/packages.md`, and `docs/design/04-in-game/` for what core draws in a game.
- `@pbgo/games` — the registry: `GAMES` (pure data: `slug`, `name`, `live`, `indexable`, `sanityProjectId`…) in `src/registry.ts`, `LOADERS` (server) in `src/index.ts`, `RUNTIMES` (client) in `src/runtime.tsx`. Adding a game = one `@pbgo-game/<slug>` package + one entry in each of the three + the dependency in `packages/games/package.json` (`pnpm new-game` does all of it). Never import a game package statically from shared code: a page loads only its game's code.
- `@pbgo-game/<slug>` — a game's binding package; the contract is in `@pbgo/core/lib/binding` (`.` isomorphic, `./ui`, `./server`, `./runtime`, `./styles.css`). Core never imports a game: it receives the `GameModule`, client components read it with `useBinding()`.
- `@pbgo/core` — the shared base: server (Supabase games with a version lock, players, admin, tasks, rate limiting), pages, route handlers, and the in-game UI: the windows a board asks a player with (`ask`, `askText`, `askNumber`, `askChoice`, drawn by `PromptHost`), the table's pieces (announcements, seat label, game over) in the game's own look, and the screen around the table (the state of the game, the social dock with the menu of the game, the players with their scores, the chat) in the platform's.
- `@pbgo/docs` — the docs of the repo as pages of the site (`/docs`): the model (sections, groups, pages, titles, links, the order of the menu, `.`), the reader of the `docs/` folder (`./server`) and the renderer of a markdown page (`./markdown`, with the platform's tokens and `Table`, and the live specimens that a `specimen` block asks for). A new doc is a new folder of `docs/` with an `index.md` whose front matter says its description (and its icon, a name registered in `apps/web/src/lib/doc-icons.ts`, the book when it names none); a new live piece is a component registered in `apps/web/src/app/(hub)/docs/_specimens/`.
- `@pbgo/analytics` — PostHog: typed events with no personal data, consent-aware browser provider (`docs/analytics.md`).
- `@pbgo/accounts` — the accounts of the hub: sign-in with Google and Discord through Supabase Auth and with Steam through the hub's own routes (Twitch is a connection: linked, never a way in; a member links and unlinks Steam from the settings) (browser, server and proxy helpers, and which providers a project has switched on), the account made of what the provider says, the safe way back after a sign-in, the second step of a sign-in (multi-factor authentication with an authenticator app, and the one place that decides who is signed in: PLT-129), the figures of a profile and the handle that names a member (a nickname and a tag, `Alex#0042`, the address of their public page, `profilePath`: PLT-39), the visitor's language (thirteen languages, kept on the account and in the cookie the games read: PLT-103), the deletion of an account (PLT-36: closed at once, reopened by the link of an e-mail) and the demo account of development (`docs/accounts.md`).
- `@pbgo/catalog` — the games the hub lists, each one as its `game` of the platform's own Sanity project (`docs/platform-sanity.md`; read through the public API with no token, cached ten minutes), Courtisans included: the live games of the registry first, then the games to come, each group in the Studio's `order` (lowest first: the games' hotness, which the Trending order of the lists is); a live game with no game there, or with the project down, gets a minimal row from the registry. The registry decides only `live` and `indexable` (and which of two live games with one `order` comes first), and a game's own Sanity project is read once one enters the game, never by the hub. The pictures are drawn from the project's image CDN, and the package also holds the route of the icons of the publishers' websites. The hub draws the list in one grid, each card opens the game's page, `/game/<slug>`, the games to come included, and that page ends with the games related to it, from the links of the Studio. It also makes the SEO of those pages: which may be indexed, their metadata, share image, JSON-LD and lines of the sitemap (PLT-56, PLT-83, PLT-90, `docs/catalog.md`), and reads the platform's editorial (announcements and changelog entries: `getEditorial`) for the signed-in home (PLT-119).
- `@pbgo/engine-kit` — the engine ↔ web contract (`GameDefinition`, `waitingFor` / `autoPlayFor`, `begin` / `nextDeadline` for a game with a clock (`Timer`, `startTimer`, `systemAction`: an engine never reads a clock, the server stamps each action with its time `at` and plays the deadline that is due, `docs/engine/02-components/20-timers.md`), `step` / `autoPlayStep` / `setupStep` (what a move says happened, which the platform keeps in the log of the table, `game_log`, and sends each player as `PublicGame.log`), `Results` and how a game ended for each player, `EngineError` and the codes every game refuses with, worded by the platform, and the conformance test of an engine) the building blocks of the card games, dice (`rollDie`, `rollDice`, `rerollDice`), counters (`changeCounter`), tracks (`moveAlong`), boards of squares and hexagons (`squareBoard`, `hexBoard` and the searches over their cells), bags (`drawFromBag`), what a player writes or chooses in a window (`cleanText`, `cleanNumber`, `cleanChoice`, `cleanChoices`, refusing with the shared `INVALID_TEXT`, `INVALID_NUMBER` and `INVALID_CHOICE`), what a player draws (`cleanStroke`, `addStrokes`, `undoStroke`: strokes of whole numbers on a grid of a thousand, bounded, refusing with the shared `INVALID_DRAWING` and `DRAWING_FULL`), the maps and the corners of a board (`graph`, `cornerGraph`, `longestTrail`: places joined by roads, with the longest road), the draft of the card games (`passAround`, `takePicks`) and the tricks of the card games (`ledSuit`, `playableCards`, `outranks`, `trickWinner`, `playOrder`). For every game the state is lean (ids and numbers only: no display data, no derived values, no log) and an order always comes from an array of the state, never from `Object.keys` (`jsonb` does not keep the order of the keys).
- `@pbgo/table` — the shared table tools of the boards (react-three-fiber): the `Table` (canvas, camera with its entrance, the endless surface the cards lie on, lights, share photo), the `Card` every game draws and the pictures it wears (`paintFace`, `standIn`), the `Die` (a die of any shape and values, rolled by physics onto the number the engine gave) and the `DiceTray` it rolls in the fields of text, number and choice (`TextField`, `NumberField`, `ChoiceField`, each a `Paper` on the table that opens a window to write or choose in) and the `Piece` and `Stack` (tokens, tiles, cubes, pawns and silhouettes), the `Counter` (a number that counts up or down), the `Stepper` and the `Slider` (a number asked on the table, without a window), the `Timer` (an hourglass that shows the time left to a step), the `Sketch` (a sheet of paper that a player draws on with the pointer, the strokes sent in batches), the `RoadMap` (places joined by roads, or the corners and sides of a board, with what can be chosen pulsing), the `Track` with its `TrackMarker` (spaces a marker walks along) the `Board` (square or hexagonal cells that can be pressed), the `Cup` (covers dice, shakes, pours), the `Bag` (tokens come out of its mouth) and the dragging of a card or a piece (`draggable`, `dropOn`, `onDrop`, the `DropZone` it is let go on, `drops` of a `Board`, `useDrag`), the layout helpers (`fan`, `row`, `pile`, `grid`, `seats`) and the `Zone` and `Pile` that place cards with them, the `Seat` (the plate of a player: name, avatar, turn crown, aura, score line and status; `PlayerSeat` fills it from the platform's table), and the debug tools of the table (`useSettings`, and the folders and helpers the `Table` adds while the debug panel is open; the panel never runs on the production deployment: `docs/engine/04-build-a-game/07-tuning.md`). It depends on core, core never imports it, and a game imports it from its lazy board chunk only (`docs/packages.md`).
- `@pbgo/ui` — shadcn components: `@pbgo/ui/game/*` (game theme) and `@pbgo/ui/platform/*` (platform theme), see `docs/design/`.
- `@pbgo/studio-kit` (shared Sanity schemas, `createStudioConfig` for a game's Studio and `createStandaloneStudioConfig` for one that is not a game's, languages, and `field-translations`: the plugin that translates fields row by row, for the platform's Studio) and `@pbgo/content-kit` (the seed pipeline of a Sanity project's content: a game's, the platform's), `@pbgo/tsconfig`, `@pbgo/eslint-config`.
- Every external dependency comes from the pnpm catalog (`catalog:`, enforced by `pnpm check:catalog`). A new workspace package used by `apps/web` goes into `transpilePackages` (`apps/web/next.config.ts`).

## Commands (from the root)
- `pnpm install` — once for the whole monorepo
- `pnpm dev` — apps/web on http://localhost:3100 (hub + every game; `pnpm dev <slug>` prints its URL)
- `pnpm dev:studio <slug>` — the game's Sanity Studio (`pnpm dev:studio platform`: the platform's)

- `pnpm lint [<path>…]` — ESLint once from the root over every package that holds code (`apps/web`, `packages/`, `games/`, `template/`, `platform/`), with one config, `eslint.config.mjs`, built on `@pbgo/eslint-config`: a new package is linted the day it is made, with no line of its own, and `pnpm lint packages/core` lints one folder. - `pnpm --filter @pbgo/platform content:seed` / `content:art` — the platform's seed (Notion rows → drafts) and the download of the Notion pictures (`docs/platform-sanity.md`)
- `pnpm --filter @pbgo/platform content:bgg [--dry-run | --apply] [--find-ids | --set-ids | --refresh]` — the missing figures of the games (complexity, players, duration, minimum age) and the BGG ids, from BoardGameGeek, as drafts to publish, or with `--refresh` the complexity brought up to date where it is still BGG's (the published documents); a dry run by default, `--apply` only on the owner's word; needs `BGG_API_TOKEN` (`docs/platform-sanity.md`)
- `pnpm catalog:list` — what the hub catalog would list right now (the live games + the published games of the platform's Sanity project) and which games of the Studio it leaves out and why; needs no key (`docs/catalog.md`)
- `pnpm new-game <slug> [--name "<Game Name>"]` — `games/<slug>` from `template/`, registered in `packages/games` (not live); the name defaults to the slug, capitalised
- `pnpm go-live <slug>` — Sanity side: project, public dataset, CORS, studio deployed, project id written in the registry, write token in `apps/web/.env.local`

## Rules of work
- English everywhere: code, comments, docs, commits, PRs. Only player-facing texts are in other languages: a game's live in its Sanity project, the platform's in `UI_TEXTS` and `translations.ts`
- Platform UI (hub, account, legal, gamemaster, 404, and the screen around a game's table) uses only `@pbgo/ui` tokens and components, never a hard-coded colour, font or spacing; a new component goes into `@pbgo/ui` first and, when other screens will use it, into a page of the docs (see `docs/design/01-guidelines/03-adding-a-component.md`); the design of one page is never documented in `docs/design/`
- Branch named after the Linear issue (`plt-<n>-<topic>`); the PR description references the issue ID; never merge your own PR
- A PR that adds a migration says so in its description: Oré runs `pnpm setup-env` right after merging it, which applies the migration to preview, then to production (see `docs/supabase-and-env.md`)
- A change that adds, moves or removes personal data (a cookie or storage key, an analytics event or property, a stored field, a processor, a request from the browser to a third party, an account feature) changes the legal pages and their inventory in the same PR (`docs/legal.md`)
- A recurring job is a skill of the agent that carries it out, `.claude/skills/<game|engine|platform>-<job>/SKILL.md`, listed in `.claude/skills/README.md`: its questions, rules and commands are written there once and other docs point to it. `CLAUDE.md` describes the codebase, it holds no procedure
- A game's texts, translations, images and sounds live in its Sanity project only, never in code (`docs/sanity-and-languages.md`)
- This file is loaded into every session, so it stays a map: the detail of an area goes into its `docs/` file, a procedure into a skill
- A lint finding is fixed in the code. An `eslint-disable` comment is for the one line where a fix would change what the code does, and says why after `--`
- Never commit secrets or env files (`.env*` except `.env.example`, `.vercel`, `.sanity-project-id` are git-ignored)
